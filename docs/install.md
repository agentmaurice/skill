# Install the AgentMaurice skill

The canonical package is `skill/agentmaurice`.

## MauriceCLI installation

Prefer the bootstrap command generated by AgentMaurice:

```bash
maurice agent connect "https://instance.example/api/v2/agent-connections/cli-bootstrap/amc_xxx" \
  --client <claude-code|codex|cursor|windsurf|generic> \
  --skill auto \
  --env <environment> \
  --agent-alias <agent-alias> \
  --dir .
```

This command accepts only the `amc_` MauriceCLI bootstrap generated by
AgentMaurice OS. An `amb_` URL is reserved for direct External Inception MCP
setup and must not be passed to `maurice agent connect`.

MauriceCLI installs the embedded package when the selected client has a native
skill format. `--skill none` disables installation. Use `--skill force` only
when the user explicitly chooses to replace a locally modified copy.

Credentials remain in the private MauriceCLI configuration. The project
contains only non-secret manifests and credential references.

## Local front door bridge

For a local One, use the front-door grant and bridge commands documented in
[`references/frontdoor.md`](../skill/agentmaurice/references/frontdoor.md).
The bridge reads a private token file and connects to an already running
loopback endpoint; it does not start the One. `maurice doctor --json` can check
the authenticated MCP catalogue when both `--mcp-endpoint` and
`--mcp-token-file` are supplied. This check is best effort and reports
`mcp_frontdoor.checked`/`mcp_frontdoor.ok`; it is not Workflow or VM
qualification.

## Assistant connection

The local assistant connection contract is also documented in
[`references/frontdoor.md`](../skill/agentmaurice/references/frontdoor.md).
It requires an explicit private `--token-file`, runs authenticated MCP
initialize and `tools/list` with a five-second timeout, and atomically writes
either Codex TOML or generic `mcpServers` JSON. It does not create grants,
start One, configure other clients, or copy bearer values into configuration.

Workflow result semantics are documented in the front-door reference: declared
`output` plus `output_schema` returns a pinned, redacted business result up to
64 KiB; legacy Workflows retain `{"ok":true}`. This is a contract description,
not evidence of a completed runtime qualification.

## Manual installation

Copy the complete `skill/agentmaurice` directory to the client's skill
directory without flattening `agents/` or `references/`.

For Codex, use the configured Codex skill home. For Claude Code, use the
project's native skill directory. Cursor, Windsurf, and generic clients may use
the bootstrap prompt and MCP contract when they do not expose a stable native
skill format.

## Codex Agent Plugin (privé)

```bash
python3 scripts/build_client_plugin.py --client codex --output /tmp/maurice-plugin
codex plugin marketplace add /tmp/maurice-plugin
codex plugin add maurice@maurice-local
```

Le paquet contient le Skill canonique et `use-maurice`. Il réutilise le MCP
déjà connecté et ne démarre pas le One ni ne crée de mandat. Si la connexion
manque, le Skill guide explicitement `maurice assistant connect codex` avec un
fichier de jeton privé. La qualification sur un One réel est séparée du
packaging.

### Projet dédié dans Codex Desktop

Ajouter le dossier comme **projet local**, puis créer le chat dans ce projet.
Joindre le dossier à un message ne charge pas son `.codex/config.toml`. Préparer
les connexions MCP du projet avant de créer le chat : dans le build Desktop
qualifié, un serveur ajouté ensuite n'apparaît pas dans le chat existant.

Le dossier source du plugin et son activation ne remplacent pas l'installation
par le client. Vérifier que le catalogue effectif expose `maurice:use-maurice`
depuis le cache installé, puis vérifier séparément les outils MCP. Une lecture
du fichier `SKILL.md` dans le dossier source ne suffit pas.

Pour limiter l'activation à un projet approuvé, utiliser un nom de marketplace
distinct et conserver ces réglages dans le `.codex/config.toml` du projet :

```toml
[marketplaces."maurice-local"]
source_type = "local"
source = "/chemin/absolu/du/paquet"

[plugins."maurice@maurice-local"]
enabled = true
```

`codex plugin add` écrit aussi `enabled = true` dans la configuration
utilisateur. L'installation n'est donc pas limitée au projet par cette commande
seule. Après installation, désactiver cette même entrée au niveau utilisateur
(`enabled = false`) et conserver l'activation du projet. Préserver les autres
réglages. Ne pas modifier manuellement le cache du plugin. Le
[rapport Codex Desktop](qualification/AGENT-613-codex-desktop.md) précise le
build testé et les limites observées ; une installation CLI isolée ne prouve
pas à elle seule le chargement dans Desktop.

## Plugin Claude Code (privé)

Pour Claude Code, construire le paquet dans un répertoire temporaire et le
charger seulement pour la session concernée :

```bash
python3 scripts/build_client_plugin.py --client claude --output /tmp/maurice-claude-plugin
claude --plugin-dir /tmp/maurice-claude-plugin/plugins/maurice
```

Le plugin utilise le MCP déjà configuré et le namespace Claude
`/maurice:maurice`. Le paquet n'ajoute aucun hook, mod ou `.mcp.json`.

Dans l'onglet Code de Claude Desktop, choisir le dossier du projet. Depuis
ce dossier, enregistrer le catalogue construit et installer en portée `local` :

```bash
claude plugin marketplace add /tmp/maurice-claude-plugin
claude plugin install maurice@maurice-local --scope local
```

La commande marketplace enregistre le catalogue dans le client ; `--scope
local` limite l’activation du plugin au projet. Pour une qualification isolée,
un nom de marketplace distinct permet de conserver une version précédente
sans confusion de cache. Les serveurs MCP restent une configuration explicite du
propriétaire. Pour les deux connexions d'un projet de qualification déjà
revues et autorisées, la sélection persistante peut être renseignée dans le
fichier non suivi `.claude/settings.local.json` :

```json
{
  "enabledMcpjsonServers": ["maurice_local", "maurice_runtime"]
}
```

Fusionner ce champ avec les réglages existants sans les écraser. Il nomme les
connexions présentes dans le `.mcp.json` de ce projet, sans créer de grant ni
autoriser les serveurs d'autres projets. Ouvrir ensuite une nouvelle session
sur ce dossier et vérifier le catalogue à chaque échange. Le
[rapport Desktop et Doctor](qualification/AGENT-1034-desktop-doctor.md)
conserve le retrait `not_configured` observé avant cette sélection et le rejeu
après configuration ; il ne conclut pas à une correction générale de Desktop.

Lors d'un fallback CLI autorisé par une règle exacte, exécuter la commande
littérale sans y ajouter `echo`, chaînage ou redirection ; lire le statut de
l'outil shell. Un refus de permission reste un refus et ne justifie pas un
autre moyen d'exécution ni une modification globale des permissions.

Les parcours `swarm` et `build`, leurs invocateurs publics, leurs preuves et
les limites restantes sont décrits dans [le rapport natif](qualification/AGENT-1034-native-interfaces.md) et
[le rejeu Desktop courant](qualification/AGENT-1034-desktop-doctor.md). Le lifecycle reste une opération
locale explicite ; une connexion MCP déjà autorisée n’impose pas la CLI.

Pour les cartes humaines, conserver aussi l’URL explicite de l’accueil du One.
Le port MCP ne permet pas de déduire le port de cette page. Si le serveur ne
retourne qu’une référence d’action, fournir cette origine au Skill pour obtenir
le lien documenté ; la décision reste dans l’interface humaine existante.

## Vocabulaire et parcours Codex

Dans Codex, l'accueil et l'usage passent par `$use-maurice` (sans syntaxe
Claude) : le guide enchaîne `maurice.search`, `maurice.explain`, puis
`maurice.execute` avec une référence exacte, le `plan_hash` attendu et une
`idempotency_key`. Les mêmes opérations sont disponibles par les commandes
CLI publiques `maurice search`, `maurice explain` et `maurice execute`.

Pour un diagnostic de connexion, utiliser :

```bash
maurice doctor --mcp-endpoint <endpoint> --mcp-token-file <token-file> --json
```

Les champs `checked` et `ok` indiquent seulement la connexion et la découverte
du catalogue MCP ; ils ne prouvent pas une exécution, une approbation humaine
ou une qualification métier.

Si le MCP manque, le branchement explicite est :

```bash
maurice assistant connect codex \
  --endpoint <endpoint> \
  --config-file <config> \
  --token-file <token-file>
```

Le chemin du fichier de jeton reste privé et son contenu n'est jamais lu dans
le parcours documentaire. Le lot Codex AGENT-613 ne livre pas de commande
d’installation automatique ni de nouveau serveur MCP. Le plugin Claude
provient du lot distinct AGENT-1034, documenté ci-dessus.

## Verify

For the canonical standalone Skill, confirm `$agentmaurice`. For the Codex
plugin, confirm `$use-maurice`. For the Claude plugin, confirm
`/maurice:maurice` and `/maurice:agentmaurice`. Then check that the following
relative references resolve from the canonical `SKILL.md`:

- `references/agent-spec-v2.md`
- `references/expert-operations.md`
- `references/modules.md`

Then run the external content lint from `test-maurice`:

```bash
AGENTMAURICE_SKILL_DIR=/path/to/skill/agentmaurice \
  task test:skill:content-lint
```

Do not validate the skill by copying real credentials, production plans, or
runtime exports into fixtures.

## Maurice diagnostic package

`skill/maurice-diagnostic` installs the same way: copy the complete directory,
without flattening `agents/` or `references/`, to the client's skill directory
(for Claude Code, `.claude/skills/maurice-diagnostic/` in the project or
`~/.claude/skills/maurice-diagnostic/`; for Codex, the configured Codex skill
home). It needs no MauriceCLI and no credential. Without installation, the
assistant can read the published copy at
`https://agentmaurice.ai/skill/maurice-diagnostic/SKILL.md`.
